Постановка задачи.
- Мы делаем исследовательскую платформу для создания разнообразных приложений путем реверс-инжениринга работающих веб-сайтов с помощью ИИ-агентов (например, VS Code + Kilo Code plugin).
- Для работы нам понадобится два компонента. 
    - MCP прокси. Локальное node.js приложение, выступающее шлюзом между ИИ-агентом. Для ИИ-агента оно выступает в качестве MCP-сервера с набором функций, позволяющих выполнять реверс-инжениринг веб-сайтов. А для JS-агента - вебсокет сервером, к которому агент присоединяется, чтобы предоставить ИИ-агенту возможность делать запросы через MCP непосредственно к runtime веб-сайта. MCP должен предоставлять минимум инструментов:
        - прочитать DOM
        - выполнить JS
        - получить данные из js-агкета
        - (иные функциИ)
    - JS-агент на сайте. Код, внедряемый пользователем, который проводит исследование. Код должен устанавливать соединение с MCP прокси, и отрабатывать поступающие от него запросы. Запросы лучше исполнять в виде наперед заданных команд, либо в качестве динамического JS, который выполняется в рантайме веб-сайта и затем другим запросом имеет возможность вернуть полученные данные (или текст ошибки, если скрипт не удался). Тут должна быть абсолютная устойчивость к ошибкам JS так как модели ошибаются, и с другой стороны, должна быть полная прозрачность по обратной связи, чтобы текст и трассировку этих ошибок через MCP-прокси можно было вернуть для доработки самой модели. Внедряемый JS агент должен иметь стабильную возможность к самообновлению, на случай, если ИИ-агнент сочтет необходимым внести исправления в его рабочий код. 
- Базовый проект для исследований (mcp, js-агент) должны быть в чистом проекте. Для всех артефактов конкретного исследования должны быть правила складирования, и пути к этим артефактам должны быть в .gitignore. Вариант использования - git clone, объясняешь LLM что ты хочешь - пилишь артефакты в подпапке исследования
